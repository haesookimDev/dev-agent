## Scope and security boundary

The root-owned `kelpie-network-hook` records new outbound connections for an exactly reconstructed Kelpie network. It does **not** enable internet egress, broaden the existing control IP:port exception or replace the Guest's deny-by-default NWFilter. General repository/model egress is a separate [explicit public-egress feature](worker-public-egress.md).

The [libvirt network hook](https://libvirt.org/hooks.html) validates the network UUID, bridge, private subnet and ownership metadata. Before activation, it requires journal readiness, writes a durable `pending` receipt, creates a scoped nftables table, reads its exact live policy/handle and writes `active`. Network activation and NIC attachment/update recheck the live identity. Missing, changed or recreated tables are refused. The hook never calls libvirt recursively, reads Worker credentials or executes a supplied command.

The forward chain has priority `-10` and logs `ct state new` for the owned bridge/source. [nftables logging](https://netfilter.org/projects/nftables/manpage.html) is non-terminating: this chain does not exempt packets from other filtering. The prefix is `kelpie-egress:<run UUID> `. Default packet headers identify the bridge, source/destination, protocol and ports; no packet payload, URL, DNS question or optional TCP/IP logging flags are requested. Packets dropped earlier by NWFilter are not promised journal records.

Root-only writes under `/var/lib/kelpie-network-guard` retain immutable `pending`, `active` and `stopped` records, with root ownership, safe parent paths, a single link, strict encoding, lock and boot identity checks. On stop, only the matching live kernel handle can be deleted. A replaced table is preserved for investigation. Journal unavailability does not prevent safely established physical teardown. Records remain after cleanup; do not delete them to bypass uncertain ownership.

This is **not lossless audit storage**. Runtime journal loss/flood detection, retention and crash recovery between kernel creation and the `active` receipt remain operational release gates. Those uncertain states fail closed; they are not silently adopted or declared cleaned up. The hook's stderr uses a fixed failure message, without privileged command output.

## First installation and maintenance

The [installer](../../infra/host/install-network-hook.sh) is opt-in and **first-install only**, for an idle dedicated Ubuntu host with libvirt, systemd-journald and nftables. Existing network hooks or guard state are refused, not overwritten. There is no new Worker environment default or API/schema migration.

Keep the reviewed installer and executable in canonical root-owned paths whose entire parent chain is not group/world-writable. The source must be a regular executable with one link, no symlink and no group/world write access. Supply its independently approved lowercase SHA256 as the second argument. The installer copies into a root-private staging directory, verifies the approved digest, installs that same protected copy and verifies the installed bytes before restarting libvirt. Changing the original source cannot change which digest is approved. No new Python/Go module dependency is introduced; it uses Ubuntu Bash/coreutils and the existing host dependencies.

Before invoking it, stop work intake, finish cleanup and establish an **effective runtime mask** on `kelpie-worker.service`. Confirm the actual systemd state is masked, inactive and runtime-masked; an absent unit, `disable` or an ineffective mask is insufficient. The installer rechecks Worker state around empty domain/active-network inventory, immediately before writing the hook and again before restarting libvirt. Keep other privileged libvirt operators out of this maintenance window; this is not a lock against a trusted administrator bypassing systemd.

The repository currently installs a local unit under `/etc/systemd/system`. That location takes precedence over `/run`, so `systemctl mask --runtime` alone may not mask it. Follow a reviewed maintenance procedure that preserves the exact existing unit and its metadata outside the load path, establishes the effective runtime mask, and restores the original after verified installation. Do not use forced replacement or delete the unit. See [systemd's mask semantics](https://github.com/systemd/systemd/blob/v255/man/systemctl.xml). A fresh host without the local unit can use the runtime mask directly; verify the resulting state rather than assuming the command succeeded.

Invoke the reviewed installer with a clean environment containing only fixed system paths, locale and `KELPIE_NETWORK_HOOK_INSTALL_ACK=dedicated-idle-host-only`, followed by the absolute reviewed binary path and approved digest. It requires root; unprivileged tests do not grant the Worker this authority. It leaves Worker intake masked rather than automatically starting work. After checking the installed digest, daemon health and a scoped lifecycle test, restore the prior unit/mask state and resume intake explicitly.

On installation or restart failure, keep intake quiesced, preserve the partial installation and receipts and resolve them through reviewed maintenance. Do not rerun with relaxed checks. For rollback/upgrade, first prove there are no owned VMs, active networks or uncertain kernel tables; preserve the hook, guard records and original metadata, restore the verified prior version, restart libvirt while idle and recheck before resuming. The first-install script deliberately does not automate this destructive replacement boundary.

The binary was built before the two fixture files were committed unchanged; that checkout difference is recorded explicitly.

- Two fresh-network-namespace kernel checks passed in 0.03 seconds each: generated policy/snapshot/duplicate refusal/handle deletion, then logger disappearance/replacement rejection. Their journal-readiness callback is injected; these checks alone do not prove real logging.
- Normal network creation and cancellation after activation, each recovered by a separate OS process, passed in 4.86 seconds. A read-only postcheck confirmed all six root lifecycle receipts and absence of their logging tables. These are network tests, not real API release tests.
- A real Golden Image Guest passed TLS to a credential-free public test endpoint, eight forbidden TCP attempts and TAP DROP `0 → 8`, in 63.96 seconds. The actual kernel journal matched this run's UUID, bridge, source, destination, TCP and port. The live table matched the root receipt; `stopped` and physical table absence preceded the fixture's synthetic local release.
- VM/network/filter/bridge/disks were removed; pre-existing network inventory and the base image hash were preserved. The base-image ACL, four ancestor ACLs and original installed hook inode/hash/owner/mode were restored. Private evidence and the tested hook binary remain preserved.

The HTTPS test used `example.com` as a transport positive control. It is not a dedicated production API listener or Runner/API acceptance. That test used exact, reversible hook replacement; it is distinct from the subsequent first-install acceptance below. No UI code changed here, so new browser/desktop screenshots are not applicable. Full GUI, sealed-image/Runner, amd64 VM and concurrent-two-work gates remain.

The final installer at `502b32b` passed a separate **actual root first installation and libvirtd restart** in the idle lab. The effective runtime mask rejected a real Worker start request. The installed binary matched the approved SHA256 and root:root 0755 metadata; the newly discovered hook then passed both network creation/cancellation/recovery cases in 4.86 seconds. Six new root lifecycle receipts were checked. New installation evidence was archived, not deleted. The receipt records exact installer/test hashes and distinguishes this maintenance exercise from initial provisioning of an unrelated production host.

Nine installer test groups passed on Linux, including source validation (0.10 seconds), source mutation races (0.56 seconds), exact inactive/runtime-mask/zero-PID parsing, inventory races and independent pre-install/pre-restart gates. Failed directory creation, binary copy or restart cannot fall through to later effects or appear successful merely because the old daemon remains active. ## Repeatable verification and CI

Run `make test-worker`, `make lint` and focused `go test -race ./internal/daemon -run '^TestNetworkLog' -count=1` from `apps/worker` for the last command. Compile and vet Linux ARM64 and amd64 `libvirt_integration` fixtures separately. Ordinary unit tests do not require root or libvirt.

The existing GitHub Go job installs Ubuntu's `nftables` package, compiles the tagged fixture once, retains tagged vet and runs only `^TestIsolatedKernelNetworkLog` under `unshare --net` with a 30-second test timeout. Tests require `KELPIE_NETWORK_LOG_TEST_ACK=disposable-isolated-netns-only`, root and a namespace different from PID 1. No additional job, VM, production secret or host firewall mutation is required; the existing eight-minute job budget remains. CI kernel checks do not replace actual VM/journal acceptance.

The separate `TestDedicatedLibvirtLoggedControlPackets` requires `KELPIE_LIBVIRT_TEST_ACK=disposable-host-only`, an explicitly prepared image, HTTPS origin and pinned IPv4 on an approved empty Linux lab with the hook installed. Run it with a six-minute outer test timeout, preserve journals and confirm physical cleanup and temporary-permission restoration on success or failure. Do not grant public CI access to a production libvirt socket or credentials.
