# Artifact HTTP cache protection

[한국어](../ko/artifact-cache.md) | English

## Behavior and compatibility

In actual Chromium, navigating to a missing file's 410, restoring only that file, then fetching the same URL from the dashboard origin produced `Failed to fetch`. Responses lacked storage prevention and Origin variation. The same regression passes after the header policy change. This is not a direct measurement of the disk-cache flag.

Lists, files and handled errors at `/api/work-items/{work-id}/artifacts` and `/api/work-items/{work-id}/artifacts/{artifact-id}` receive `Cache-Control: no-store` and `Vary: Origin`, including navigations without Origin. Existing Vary fields remain; allowed origins, authentication and authorization are not expanded. Compliant private and shared HTTP caches must not store or reuse these responses. [RFC 9111](https://www.rfc-editor.org/rfc/rfc9111.html)

- Existing meanings/bodies remain: 200 success, 401 authentication required, 403 revoked access, 404 another organization/missing metadata, and 410 unavailable content. HEAD 405 and trailing-slash 307 are also covered.
- Original bytes, UTF-8 filenames, `Content-Security-Policy: sandbox` and `X-Content-Type-Options: nosniff` remain. Uploads, SSE, event lists, health and WebSocket paths are excluded.
- Pure ASGI changes response-start headers without buffering bodies or catching exceptions. This does not change global error handling or cover unhandled 500 responses generated by the outer `ServerErrorMiddleware`. [Starlette Middleware](https://starlette.dev/middleware/)

## API example and operation

An authenticated owner's `GET /api/work-items/{work-id}/artifacts/{artifact-id}`:

```http
HTTP/1.1 200 OK
Cache-Control: no-store
Vary: Origin
Content-Type: text/plain; charset=utf-8
Content-Disposition: inline; filename="owned-evidence.txt"; filename*=UTF-8''owned-evidence.txt
Content-Security-Policy: sandbox
X-Content-Type-Options: nosniff

Owned artifact acceptance evidence
```

Missing content returns `410 {"detail":"artifact content is unavailable"}`; membership revocation returns `403 {"detail":"organization membership required"}`, retaining storage prevention. Successful lists keep their JSON array. No schema, environment variable/default, dependency or database migration is added.

During deployment, ensure the API and upstream proxy/CDN preserve these headers and do not force caching on either route. Headers cannot retroactively erase old cached responses or user-downloaded files. For managed caches, expire only existing artifact-route entries under the deployment procedure and verify fresh requests. Do not hide regressions by clearing all user caches or disabling caching. For rollback, suspend affected serving and restore a corrected version instead of re-enabling sensitive-response storage.
