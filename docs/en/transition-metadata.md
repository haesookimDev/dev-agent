# Authoritative state in transition history

[한국어](../ko/transition-metadata.md) | English

## Contract and impact

Top-level payload `from`/`to` in `work.transitioned` events generated by `transition_work_item` are the control plane's actual previous/next states. Caller-supplied conflicting keys cannot overwrite them. Other fields, nested `from`/`to`, explicit messages, actors and correlation IDs remain intact; input is copied. [API ingress redaction](api-event-redaction.md) still applies.

Example `POST /api/runs/{id}/transition` with a valid work lease:

```json
{"status":"analyzing","expected_version":2,"payload":{"from":"awaiting_approval","to":"completed","safe":17}}
```

With current state `provisioning` and version 2, the response work has state `analyzing` and version 3. The stored event, event log and SSE contain payload `{"from":"provisioning","to":"analyzing","safe":17}`. This endpoint returns a WorkItem, not the event itself. No client changes, schema migration, new environment variables or dependencies are required. Retention of incorrect conflicting values intentionally changes.

Applies to Worker transitions, claims, feedback, approvals, quarantine and delivery using the common function. No changes to the state graph, version conflicts, lease validation, user authorization or approval policy. Web refreshes the actual WorkItem rather than trusting payload states directly. This fixes transition-record integrity, not a directly forged display state.

## Remaining boundaries and rollback

Historical events are not rewritten. Arbitrary event type/source/payload accepted through the separate `/events` ingress remains caller data. An event named `work.transitioned` alone is not universally trustworthy. Truthfulness of arbitrary messages/nested states, event provenance and caller-specific transition authority are separate concerns. This does not replace actual OIDC HTTPS browser mutation, concurrent KVM/isolation, Preview verification or full MVP completion.

Use a normal revert of the API change if needed. There is no migration, but the older version allows conflicting payloads to distort transition history again. Do not disable existing credential redaction, authentication or approval checks.
