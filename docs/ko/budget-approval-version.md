# 확인한 버전에 대한 시간 예산 승인

한국어 | [English](../en/budget-approval-version.md)

## 계약과 클라이언트 전환

`POST /api/work-items/{id}/approvals`의 `kind=budget`은 승인·거절 모두 최상위 `expected_version`을 요구합니다. 사용자가 확인한 WorkItem의 `version`을 **양의 JSON 정수**로 보내세요. 예를 들어 버전 4의 예산 소진 작업에 15분 연장은 다음 요청입니다.

```json
{"kind":"budget","decision":"approve","expected_version":4,"payload":{"minutes":15}}
```

성공은 기존 WorkItem JSON(200)입니다. 위 작업의 기존 예산이 240분이면 `status=implementing`, `version=5`, `budget_minutes=255`가 됩니다. 거절은 예산·상태·버전을 바꾸지 않고 결정을 기록합니다. 따라서 같은 버전의 거절 뒤 새 승인은 가능하며, 이 계약은 모든 결정의 Idempotency Key가 아닙니다.

버전 생략·`null`·Boolean·문자열·소수 표기·0 이하 정수·배열·객체는 422입니다. 예산 결정의 버전 생략·`null` 오류는 `{"detail":"expected_version is required for budget decisions"}`이고, 다른 타입 오류는 표준 입력 검증 응답입니다. 이전 또는 미래 버전은 409와 `{"detail":"version mismatch: current version is 7"}` 같은 응답입니다. 실패하면 예산·작업·승인·활동·감사·전달 예약을 변경하지 않습니다. 권한·조직·Worker 격리 경계는 유지합니다. 타입이 올바른 요청의 권한 검사가 버전·상태 검사보다 먼저 수행됩니다.

이는 기존 **예산 결정 요청에 대한 호환성 변경**입니다. 호출부에서 작업을 조회하고 사용자에게 그 상태와 연장량을 보여준 시점의 버전을 보관하여 전송하도록 전환하세요. 409나 응답 유실 후에는 최신 작업을 다시 조회하고 사용자에게 변경 결과를 확인시킵니다. 버전만 자동 갱신하여 이전 의도를 재전송하면 안 됩니다. 버전 필드를 생략하던 PR·Console 승인 요청은 계속 동작합니다. Slack PR 승인 및 Worker 명령 형식은 바꾸지 않습니다. 예산 활동 이벤트에는 확인 버전이 추가되며 감사의 기존 전후 버전 필드를 유지합니다.

기존 15~1440분 정수 연장·생략 기본값 60분과 Approver 권한은 그대로입니다. DB Migration·새 환경변수·의존성은 없습니다. API와 예산 호출부의 배포를 조정하세요. 이전 API로 되돌리면 버전 검사가 없어지므로 예산 승인 기능을 사용하지 않고 전진 수정해야 합니다. 감사 삭제나 승인 게이트 해제로 복구하지 않습니다.

## 회귀 및 실제 사용 검증 · 2026-09-09

구현 `b5c92ac`, 실제 HTTP/경합 회귀 `d61cc5f`, CI `ebd9346` 기준입니다. 후속 문서는 실행 코드를 변경하지 않습니다.

- 수정 전 새 테스트 30개 중 24개 실패·6개 통과를 재현했습니다. 수정 후 기존 권한·감사·Runner 회귀를 포함한 152개가 통과했습니다. 별도 실제 OIDC Session/Scoped Worker HTTP 회귀도 예산 소진→승인→재소진→이전 승인/거절 거부→현재 버전 거절/승인과 감사 보존을 검증합니다. 외부 IdP·VM·SCM은 사용하지 않습니다.
- PostgreSQL의 잠긴 행을 기다린 뒤 최신 버전 확인, Rollback 후 승인, 동시 중복 승인 및 감사 실패의 원자성 네 경우가 통과했습니다. 기존 취소/Claim 네 경우와 함께 8개가 3.24초에 통과했습니다. 필수 `Python` CI의 기존 PostgreSQL Step에 추가하여 새 Job·Matrix·Timeout을 만들지 않았습니다.
- 전용 임시 PostgreSQL DB의 `make test`: API 1,197개(223.52초, Skip 없음), Runner 45개, Worker/Gateway, Web 91개·타입 검사 통과. `make lint` 통과. 기존 Web E2E·빌드와 최신 Head CI 결과는 PR에 기록합니다.

- Orca 브라우저의 한국어 1100×900, 영어 390×844 최종 화면과 실시간 상태/예산/버전, 가로 넘침 없음, 관측 구간 네트워크 64건 모두 200·외부 요청 0·콘솔 오류 없음을 확인했습니다. 최초 일회용 로그인 경유 주소의 404는 세션이 설정된 실제 페이지로 이동해 해소했습니다. 1440px 캡처의 중복 타일 이미지는 최종 증거에서 제외하고 다시 관측했습니다.

검증용 API·Web·브라우저를 종료하고 직접 생성한 임시 데이터만 정리했습니다. API 종료 로그와 DB의 자격증명 비노출 검사를 통과했으며 기존 사용자 프로세스·DB는 보존했습니다.
