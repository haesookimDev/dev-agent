# 소진된 시간 예산 연장

한국어 | [English](../en/budget-approval-ui.md)

## 사용자 흐름

예산이 소진된 작업의 제어 영역에 연장 안내와 `시간 연장 검토…` 버튼을 표시합니다. 피드백만으로 시간이 늘어나지 않는다는 점을 안내하며, 확인 창에서 대상 작업·추가 시간·기존 예산·연장 후 총예산을 검토합니다. 한국어와 영어를 함께 제공합니다.

추가 시간은 15~1,440분의 정수이며 기본 입력은 60분입니다. 빈 값·범위 밖·소수 입력은 제출할 수 없습니다. 돌아가기와 Esc는 승인하지 않고 창을 닫습니다. 최초 포커스는 돌아가기에 놓이며, 성공 후 사라지는 버튼 대신 상태 영역으로 포커스를 옮깁니다. 승인 응답 대기 중에는 입력·버튼·Esc를 잠가 중복 제출을 막습니다.

기존 [예산 승인 계약](budget-approval-version.md)을 사용합니다. 확인 창을 연 시점의 `version`을 고정하여 `kind=budget`, `decision=approve`, `expected_version`, `payload.minutes`를 전송합니다. 성공하면 응답의 예산·상태를 반영하고 **개발 재개 요청**을 안내합니다. 실제 Runner 진행이나 완료를 보장했다는 뜻이 아니며, 커밋·PR 전달에는 별도 승인이 필요합니다.

버전 충돌·실시간 상태 변경이 있으면 기존 확인은 제출할 수 없습니다. 창을 닫고 최신 예산을 다시 검토해야 합니다. 응답 유실 뒤에는 최신 작업을 조회하지만 확인 버전을 자동 교체하지 않습니다. 성공을 확인하지 못한 경우 성공 안내를 표시하지 않으며, 권한 거부도 별도로 설명합니다. API의 Approver/관리자 권한·조직 경계·추가 전용 감사는 그대로 유지합니다.

## 재현 가능한 검증

- `make test-web`: 단위 테스트 125개와 타입 검사. 잘못된 분·버전·상태 및 양 언어의 상태별 표시를 검증합니다.
- `make lint`: Ruff·Go vet·Web ESLint. 테스트 전용 Python은 `.venv/bin/python -m ruff check apps/web/e2e/budget-runtime.py`로 추가 확인합니다.
- `npm run test:e2e --prefix apps/web -- budget.spec.ts cancellation.spec.ts`: 실제 Chromium·Next·API에 연결한 신규 연장 6개와 기존 취소 6개가 통과했습니다. 기본 E2E 명령과 기존 `Web` CI에도 자동 포함됩니다.

새 회귀는 정상 승인, 390px 확인 창과 키보드 포커스, 입력 제한, 대기 중 중복 제출, 통신 실패 후 명시적 재시도, 다른 승인·재소진 이후의 409, 성공 응답 유실과 SSE 변경을 검증합니다. 예산·버전·감사 행도 실제 API에서 조회합니다. 403 화면 처리는 명시적인 응답 Fixture이고 실제 OIDC 권한 검사는 API 회귀에서 수행합니다.

테스트 환경은 매번 새 SQLite DB에 명시적인 개발 인증을 사용합니다. 별도 Scoped Worker 자격증명으로 실제 Claim·상태 전환·해제 API를 호출하며 VM이나 모델 실행으로 주장하지 않습니다. Worker 토큰·임대는 새 0600 파일에만 저장하고, 테스트가 끝나면 해당 임대를 해제한 뒤 기존 공통 해제 검사를 유지합니다. `KELPIE_E2E_BUDGET_METADATA`는 Playwright가 생성·전달하는 임시 메타데이터 경로이며 제품 설정이 아닙니다. 외부 계정이나 운영 환경을 탐색하지 않습니다.

CI에 새 Job·Matrix·의존성·Timeout은 추가하지 않습니다. 기존 8분 `Web` Job과 `browser-evidence`에 확인 창 스크린샷도 보존합니다. 새 환경변수·DB Migration·API 변경은 없습니다. 롤백은 Web 변경을 되돌리되 기존 API의 버전 검사와 감사·승인 정책을 유지합니다.

전체 `make test`는 전용 임시 PostgreSQL DB에서 API 1,197개(225.57초, Skip 없음), Runner 45개, Worker·Gateway, Web 125개·타입 검사를 통과했습니다. 실제 화면 검토에서 발견한 버튼 스타일 누락은 양 언어의 수정 전 실패를 재현한 뒤 공통 디자인을 적용했습니다. 확인 창의 과한 간격을 줄이고, 양 언어에서 320×568 화면의 가로 넘침·버튼 접근성과 최소 44px 높이를 추가 검증합니다.

실제 VM의 시간 강제, 실행 중 취소, Linux/KVM·WireGuard/noVNC의 동시 작업 격리 및 MVP 전체 완료는 별도 검증입니다.

## 실제 운영 빌드 확인 · 2026-09-09

구현 `c4127a9`, 브라우저 회귀 `5d4bb67`, 실제 사용 후 디자인 수정 `aee5c46` 기준입니다. 최종 전체 E2E 39개가 2.4분에 통과했고 운영 빌드·정적 검사도 통과했습니다.

직접 만든 격리 API `:18500`과 운영 Web `:13500`에서 Orca 브라우저로 확인 창을 열고 실제 입력·승인을 수행했습니다. 한국어의 15.5분 입력은 거부되고 15분 승인은 30분/v4→45분/v5로 반영됐습니다. Scoped Worker가 다시 소진시킨 v7이 영어 화면에 SSE로 나타났으며, 20분을 검토하고 키보드로 승인하여 65분/v8과 정확히 2개의 승인 감사 행을 확인했습니다. 영어 모바일의 문서 폭은 375px, 확인 창의 표시/내용 폭은 모두 339px로 가로 넘침이 없습니다. 화면 밖 버튼의 첫 CLI 클릭은 창을 열지 않아 결과를 확인한 뒤 스크롤·포커스·Enter로 실제 개방을 검증했습니다.

관측 구간의 두 승인 POST는 모두 200이고 콘솔 오류·외부 요청은 없습니다. 운영 Web 재시작 직후의 한 탐색은 연결 거부였으며 준비 상태 200을 확인한 뒤 다시 탐색해 정상 동작을 검증했습니다. Computer-use는 데스크톱 캡처를 제공했지만 복원 후에도 포커스가 없어 네이티브 클릭을 거부했습니다. 재시도를 중단했으며 네이티브 입력 성공이나 실제 VM 실행으로 보고하지 않습니다. 시스템 신뢰·인증·Origin 경계를 바꾸지 않았습니다.
